## 1. 用户和痛点（所有设计决定从这里推出来）

| 痛点 | 真实心理 | 设计对策 |
|---|---|---|
| 记账太烦，坚持不到一周 | 每次记账都要 5 步以上，觉得不值得 | 首页常驻数字键盘：**输入金额，按「记下」，2 到 4 下完成**，不弹系统键盘，分类可以不选 |
| 看到超支就自责，干脆不打开 | 羞耻感会让人逃避 | 永远不用红色大字骂人；超支就自动摊到后面几天，文案只说「明天小一点就好」 |
| 数字太抽象，没感觉 | 「本月剩余 4,053」没有画面感 | 把每天的额度变成**一颗梨**，梨里的果汁就是今天剩下的钱，花一笔就少一截 |
| 想买东西时不知道该不该买 | 花之前没有任何反馈 | **花之前先试算**：输入金额还没按「记下」，梨里就出现一条虚线，显示「记了以后剩多少、明天剩多少」 |
| 月底钱没了，存钱永远靠剩 | 存钱要等「剩下的」，所以总是存不下 | 发工资那天有一个小仪式：**先把存款拖进梨罐**，剩下的才分成每天的梨 |
| 用了几天就忘了打开 | 没有每天打开的理由 | 每天早上会长出一颗新梨；一个月下来积累成一张「梨园」日历，可以分享；可以把工具加到手机桌面 |
| 换手机数据就没了 | 害怕白记了 | 设置里提供导出 / 导入备份，一段文字即可 |

一句话定位：**每天打开 1 秒看一眼，花钱时 3 秒记一笔，发工资那天 10 秒完成一次「先存后花」。**

## 2. 核心创意：「一天一颗梨」

- 每个周期 = 一片梨园；每天 = 一颗梨。
- **梨身是容器**，里面的果汁高度 = 今天剩余 ÷ 今日额度。
- 花钱时果汁下降，水面晃一下再平静下来；超支时梨被咬掉一口（梨的边缘出现缺口），缺口的大小对应超支金额，最多占梨宽的 35%。
- 今天没花完，果汁就留在梨园里，明天的梨会更大一点。
- 过去的每一天在「梨园」日历里是一颗小梨：守住了是完整的梨，超了是被咬过的梨，没记录是虚线轮廓。
- 品牌一致：像素小梨只用在页面左上角当品牌标；主视觉的梨用**平滑的矢量线条**，显得高级，和游戏厅的像素风区分开。

### 3.4 梨形容器（SVG）
- 一条平滑路径画出梨身（宽高比约 0.78），顶部有一根短梗和一片叶子，线宽 1.5px，颜色用 `--ink`，透明度 0.85。
- 果汁 = 渐变填充，用梨形 `clipPath` 裁切。水面是一条正弦波路径：平时振幅 3px，每秒约 0.6 个周期；液位变化时振幅升到 10px，1.2 秒内衰减回去。
- 液位变化用弹簧动画（刚度 170、阻尼 18）。
- **试算虚线**：输入金额时，在目标液位画一条 1px 虚线，同时数字区显示 `¥152 → ¥117`，目标数字用 `--ink-2`。
- **咬痕**：超支时在梨身右上方用 `mask` 挖出一个圆，半径 = min(35% 梨宽, 超支额 ÷ 今日额度 × 梨宽)。出现时配一个 180ms 的「咔」缩放动画（scale 0.96 → 1）。
- 可选彩蛋（P2）：手机倾斜时水面跟着微微倾斜（DeviceOrientation，最大 ±8°）。iOS 需要用户点一下授权，不授权就不显示这个效果。
- 设备开启「减少动态效果」时：关闭波浪和弹簧动画，液位直接跳到目标值。

## 4. 交互规范

### 4.1 记一笔（P0）
1. 点数字键输入金额，最多 2 位小数，最大 99,999。
2. 每按一个键都实时**试算**：梨里出现虚线，副信息行变成 `记下后：今天剩 ¥117 · 明天 ¥150`。
3. 分类条在第一次按数字键后淡入；选不选都行，再点一次取消。
4. 点「记下」：果汁降到虚线位置并晃动；梨上方出现一个 4 秒的「撤销」小胶囊；键盘清空；安卓设备调用 `navigator.vibrate(12)`。
5. 点「+收入」后再点「记下」，这笔就记为收入，摊到剩下的每一天；果汁上升，配一个金色的波纹效果。
6. **大额拦截**（P1）：金额 ≥ max(3 × 今日额度, 500) 时，点「记下」后先弹出一个底部选择层：
   - A「摊到剩下 N 天」（默认）：显示每天会少多少；
   - B「从梨罐里出」：显示梨罐 ¥S 会变成 ¥(S−a)，这笔不占用每天的额度；
   - C「就算今天的」：和 A 的计算结果相同，只是文案不同，用来尊重用户的选择。
   这个弹层只出现一次，不需要用户再确认第二次。

### 4.2 每天第一次打开（P1）
- 新的一颗梨从上方落进容器：420ms，`cubic-bezier(.2,.8,.2,1.2)`，落定后水面晃一下。
- 如果昨天一笔都没记，梨下方出现一行：「昨天花钱了吗？ [没花] [补一笔]」。点「没花」把昨天标为守住；点「补一笔」，下一笔记账会算到昨天。这样用户不会因为漏记而中断连续记录。

### 4.3 发工资仪式（P1，每个周期只出现一次，任何时候都可以点「跳过」）
在新周期第一次打开时，以全屏浮层出现：
1. 如果有上一期，先出一张结算卡：「上一期守住 22/31 天，多出 ¥320」，给两个按钮：[存进梨罐] [滚到这个月]。超支的话只显示「上一期超了 ¥X，这一期已经重新开始」，只有一个「知道了」按钮。
2. 「发工资啦 ¥8,000」：固定支出逐条以灰色块滑出，比如「房租 ¥2,500」。
3. 「先喂饱未来的自己」：一个可以往上拖的金色梨罐把手，吸附在 0%、10%、20%、30% 和用户的计划值；旁边实时显示「每月 ¥800，一年 ¥9,600」。按钮有 [我已转好] 和 [稍后提醒]。选「稍后提醒」，首页梨罐图标上会挂一个小金点，直到转好为止。
4. 剩下的钱变成「¥4,600 → 31 颗梨，每颗 ¥148」：一个大液面分裂成小梨，依次落进日历，总时长不超过 1.2 秒。
整个仪式控制在 10 秒以内，所有动画都可以点击跳过。

### 4.4 底部三个入口（底部弹层，不跳转页面）
- **梨园**（P1）：本周期的月历网格，每格是一颗小梨。守住 = 实心梨，超了 = 咬痕梨，没记录 = 虚线，今天 = 呼吸描边，未来几天 = 虚线梨加上预计额度的小字。顶部显示三个统计：守住天数、最长连续天数、平均每天花多少。点某一天，展开那天的记录，可以删除。
- **梨罐**（P1）：一个大的金色罐子，里面装着累计存款；应急金目标用一个圆环表示（目标 = 3 × (到手 − 每月存款)），并写出「再存 N 个月就够」；下面列出最近 6 期的结算记录。
- **设置**（P0）：首次设置用的那句填空（见 4.5）、固定支出明细、**导出备份**（复制一段 JSON 文本）、**导入备份**（粘贴后先校验再覆盖）、清空数据（需要二次确认）。

### 4.5 首次使用：一句话填空（P0）
```text
我每月 [10] 号发工资，到手 [¥ 8,000]，
固定要付 [¥ 2,600 ▸]，想先存 [10%]。
```
- 每个方框点开后，用同一套数字键盘输入。「固定要付」点开是一个明细弹层，提供快捷标签：房租、房贷、话费网费、交通卡、会员订阅、保险、给家里、还信用卡。
- 下面实时显示一颗梨，并写出「每天 ¥148」。如果固定支出加存款超过了工资，梨就是空的，并提示「固定支出和存钱超过了工资，调一下」。
- 第二行小字（可选）：「这次发工资后已经花了 [¥0]」。
- 按钮「种下第一颗梨」。

## 6. core 区块需要新增的函数（纯函数，必须有测试）
- `preview(D, today, amount, isIncome)`：返回 `{todayLeft, tomorrow, level}`。实现方式：深拷贝 D，追加一笔记录，再调用 `compute`。
- `compute` 扩展：过滤掉 `src==='save'` 的记录，这些记录不计入每天额度。
- `dayStatus(D, k)`：返回 `'kept' | 'over' | 'blank' | 'future'`。规则：当天花费 ≤ `D.days[k].allow` 为守住；没有记录且 `zero` 不为 true 为 blank。
- `streak(D, today)`：从昨天往前数连续 kept 的天数（`zero` 算 kept），遇到 blank 或 over 就停止。
- `carryOver(D, amount)`：在新周期第一天写入一笔 `{a:-amount, c:'结转'}`。
- 把 `D.days[today].allow` 写入快照时，要用当天开始时的额度（`remainStart / daysLeft`），不受当天花费影响。

## 7. 必须补充的测试（写进 `core.test.js`）
1. 试算不修改原数据，结果和真实记下一笔后的计算一致。
2. `src:'save'` 的记录不影响每日额度，但 `savedTotal` 由调用方扣减。
3. 结转 ¥320 之后，新周期的每日额度增加 320 ÷ 本期天数。
4. streak：「守、守、没花(zero)、守」算 4 天；「守、空白、守」算 1 天。
5. dayStatus：花费等于额度时算守住，超过 1 分钱算超了。
6. 旧版本保存的 v1 数据（没有 days 和 ui 字段）可以正常加载，并且能算出结果。
